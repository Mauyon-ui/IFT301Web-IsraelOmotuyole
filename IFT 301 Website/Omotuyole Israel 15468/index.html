Assignment 1: Explain the Concept of MVT and MVC

1. Model-View-Template (MVT)

MVT is a design pattern similar to MVC, mainly used by Django (Python framework).The major difference is that Django handles most of the Controller logic internally, and developers mainly focus on the Model, View, and Template.

  • Model: Defines the structure of the data and handles all database operations.
  • View: Contains the logic that determines what data is displayed and how.
  • Template: The user interface written in HTML that displays the data.

Example: In Django, models handle database tables, views manage logic, and templates show the data to users.

2. Model-View-Controller (MVC)

The MVC pattern is a popular design structure used in frameworks like Laravel, Ruby on Rails, and ASP.NET. It separates the application into three main layers:

  • Model: Handles data and business logic.
  • View: Displays the user interface.
  • Controller: It acts as a bridge between the Model and View, processing user input and updating data accordingly.

Example: In Laravel, the controller manages requests, the model connects to the database, and the view shows data.

Assignment 2: Types of Client–Server Architecture

What Is Client-Server Architecture?
A client-server architecture is a system that hosts, provides, and manages most of the resources and services that the client requests. This approach, also known as the network computing model or client-server network, involves the delivery of all requests and services across a network.

Types of Client–Server Architecture

  • Two-Tier Architecture:
    This is the simplest type. The client communicates directly with the server.
    Example: A web browser (client) sending requests directly to a database server.
  • Three-Tier Architecture:
    It includes three layers i.e Client, Application Server, and Database Server.
    The middle layer (application server) handles business logic between the client and database.
    Example: A web app where the browser talks to a backend (like Django or Node.js), which then connects to a database.
  • N-Tier (Multi-Tier) Architecture:
    It extends the three-tier model by adding more layers for services like authentication, caching, or APIs.
    Example: Enterprise-level systems or cloud-based applications with multiple service layers.
  • Peer-to-Peer (P2P) Architecture:
    Unlike traditional client-server models, every node (computer) acts as both a client and a server.
    Example: File-sharing systems like BitTorrent or blockchain networks.
  • Distributed Architecture:
    In a distributed system, multiple servers work together as a network of servers to serve client requests. Each server may handle different tasks or duplicate the same service for reliability.
    Example: Google Search uses distributed servers across the world to handle billions of requests efficiently.

    • Note: The choice of architecture depends on the application's scale, security needs, and performance goals. Modern web applications often use three-tier or multi-tier models for better scalability and maintenance.
